# TASK-010 — Railway и Vercel staging

Контур для тестовой приёмки на синтетических данных и утверждённом начальном выпуске. Источник кода фиксируется по проверенному SHA. Базовый `main` `359a2b1` прошёл [MVP CI](https://github.com/Enot3D/ENOT-Business-Platform/actions/runs/43216451150).

## Состояние и бюджет

При инвентаризации в Railway staging были три сервиса и том 1024 МБ, все в staged. Публичных доменов API и TCP-прокси PostgreSQL не было. В команде Vercel `enot3d` проект `enot-business-platform` отсутствовал. До подтверждения бюджета staging не запускается.

Расчёт для 30 дней по [тарифам Railway](https://docs.railway.com/pricing) в USD. Память и CPU в таблице — предполагаемые средние за месяц для одного экземпляра каждого сервиса. Измерений staging пока нет.

| Ресурс | Малый пилот | Более активный пилот |
| --- | ---: | ---: |
| API | 0,15 ГБ и 0,02 vCPU → $1,90 | 0,25 ГБ и 0,08 vCPU → $4,10 |
| Воркер | 0,12 ГБ и 0,01 vCPU → $1,40 | 0,20 ГБ и 0,04 vCPU → $2,80 |
| PostgreSQL | 0,20 ГБ и 0,02 vCPU → $2,40 | 0,35 ГБ и 0,08 vCPU → $5,10 |
| Том | 1 ГБ → $0,15 | 1 ГБ → $0,15 |
| Внешний трафик, в том числе ответы API в Vercel | 2 ГБ → $0,10 | 10 ГБ → $0,50 |
| **Итого Railway до зачёта подписки** | **$5,95** | **$12,65** |

Из суммы вычитается только доступный остаток включённого использования. Налоги, конвертация, расходы Vercel и отдельное хранение резервных копий в расчёт не входят. Биллинг Railway и Vercel для этих аккаунтов требуется подтвердить отдельно. До запуска проверить остаток кредитов, потребление остальных проектов, применимый курс и резерв на налоги и задержку учёта. Ограничение в 500 ₽ относится к совокупным дополнительным расходам.

Railway поддерживает [hard limit Compute](https://docs.railway.com/pricing/cost-control) на весь workspace. Остановка по такому лимиту может затронуть другие проекты. Лимиты CPU/RAM отдельных сервисов ограничивают ресурсы, а расход зависит от фактического использования и трафика. На Vercel [Spend Management](https://vercel.com/docs/spend-management) зависит от тарифа, действует на команду, учитывает расход с задержкой и приостанавливает production-развёртывания. Его нельзя считать жёстким пределом расходов для Preview. Изменение лимитов на уровне workspace или команды требует учёта других проектов владельца.

## Конфигурация Railway

Использовать существующие сервисы проекта `77d0db96-8833-406f-baa6-5fc5bc256f4d` в окружении `8bf08f8b-f22f-4102-97dc-106ef39cd81e`. Собирать из корня репозитория, чтобы Dockerfile API и воркера включал источники TASK-002, калькулятор и аудит TASK-003, OpenAPI TASK-004.

| Сервис | Сборка и запуск |
| --- | --- |
| `enot-postgres` | [Dockerfile PostgreSQL 16](../infra/railway/postgres.Dockerfile). Существующий том монтируется в `/var/lib/postgresql/data`. Порт 5432 доступен по приватной сети. |
| `enot-api` | [Dockerfile backend](../infra/backend.Dockerfile), Python 3.12. Команда `sh -ec 'exec uvicorn enot_api.main:app --host 0.0.0.0 --port "${PORT:?}"'`. Healthcheck `/readyz`, таймаут 120 с. Pre-deploy `sh -ec 'alembic upgrade head && python -m enot_api.cli import'`, таймаут 180 с. Публичный HTTPS выдаётся Railway. |
| `enot-worker` | Тот же Dockerfile. Команда `python -m enot_api.cli worker`, перезапуск `ON_FAILURE` до десяти попыток, один экземпляр. Сервису достаточно приватной сети. |

Переменные задаются через настройки окружения Railway. Генерировать независимые пароли и ключ подписи криптографически стойким генератором, передавать по защищённому каналу и не выводить значения в терминал и отчёты. Пароль `DB_APP_PASSWORD` использовать в URL-безопасной форме, например из hex.

| Сервис | Переменные |
| --- | --- |
| PostgreSQL | `POSTGRES_USER=postgres`, `POSTGRES_DB=enot`, отдельные секреты `POSTGRES_PASSWORD` и `DB_APP_PASSWORD`. Инициализация пустого тома создаёт ограниченную роль `enot_app`. |
| API и воркер | `DATABASE_URL=postgresql+psycopg://enot_app:${{enot-postgres.DB_APP_PASSWORD}}@${{enot-postgres.RAILWAY_PRIVATE_DOMAIN}}:5432/enot`. |
| Только API | `PORT=8000`, отдельный секрет `APP_SIGNING_KEY` длиной не менее 32 байт, `APP_COOKIE_SECURE=true`, `APP_ORIGIN=https://<стабильный-домен-staging-frontend>` без пути и завершающего слеша. |
| Только воркер | `AI_PROVIDER=local`. Ключ внешнего провайдера для этого режима не требуется. |

Сначала убедиться, что staged patch не содержит удаления ресурсов. В новом окружении, если применение запускает сборки одновременно, проверить готовность PostgreSQL, затем при необходимости повторить деплой API, чтобы миграции и импорт прошли, и только затем повторить деплой воркера. На существующем томе PostgreSQL запускает init-скрипт только при первой инициализации. Перед изменениями существующей схемы сделать резервную копию. Успешный повтор CLI-импорта должен вернуть тот же ID и хеш выпуска. Для нового тестового владельца использовать интерактивную команду `python -m enot_api.cli create-user <login>` из контейнера API, передавая пароль через защищённый ввод. Публичная регистрация исключена из пилота [архитектурой](../architecture/TASK-004/security-design.md).

## Конфигурация Vercel

Подключить GitHub-репозиторий `Enot3D/ENOT-Business-Platform` к проекту `enot-business-platform` в команде `enot3d`. Root Directory — `frontend`, Framework — Next.js, Node.js 24, сборка — `npm run build`. Выбрать стабильный HTTPS alias для staging и использовать его в `APP_ORIGIN`. Проверяемое staging-развёртывание должно использовать согласованный Git SHA, а автоматические развёртывания следует включать только в пределах утверждённого бюджета.

Установить `API_INTERNAL_ORIGIN` на публичный HTTPS origin Railway API. Несмотря на имя переменной, приватный `*.railway.internal` недоступен из Vercel. Переменная считывается при сборке и не является `NEXT_PUBLIC_*`. Системные переменные Vercel должны быть доступны при сборке. [Next.js rewrites](../frontend/next.config.ts) передают `/api/v1/*` на Railway, а браузер обращается к тому же origin, что и интерфейс. Сервер проверяет Origin и CSRF. При проверке убедиться, что прокси передаёт `Set-Cookie` и `Cookie`, cookie остаётся host-only с `Secure`, `HttpOnly` и `SameSite=Lax`, а запрос записи с чужим Origin отклоняется.

## Проверки после запуска

1. Проверить `/healthz` и `/readyz` по HTTPS, приватное подключение к PostgreSQL, ревизию Alembic и повторный импорт.
2. Создать тестовую учётку через CLI. Проверить вход, выход и 401 после выхода, а также отказ при неверном Origin и CSRF.
3. Использовать [Playwright-сценарии пилота](../frontend/tests/pilot.spec.ts) с `ENOT_E2E_ORIGIN`, `ENOT_E2E_LOGIN` и `ENOT_E2E_PASSWORD` из изолированного окружения проверки. Сверить 20 ниш, фильтры, сравнение, финансовые сценарии, локальную сводку воркера, создание исследования и чтение сохранённого снимка. Проверить Chromium на 1440, 768 и 390 px.
4. Последовательно перезапустить API и воркер и повторить готовность, чтение исследования и обработку нового задания. Отдельно проверить PostgreSQL в согласованное окно, убедиться, что данные сохранились, а соединения восстановились.
5. Сверить логи и метрики CPU, RAM, диска, egress и рестартов с прогнозом расходов. Ключи, пароли, cookies и строки подключения из логов исключаются.

## Резервное копирование и откат

После запуска создать логический архив `pg_dump -U postgres -d enot -Fc` из доверенной среды с приватным доступом к PostgreSQL. Передавать архив зашифрованным каналом в согласованное хранилище с ограниченным доступом. Не включать публичный TCP ради копирования. Для восстановления подготовить отдельную тестовую БД с ролью `enot_app`, затем выполнить `pg_restore --single-transaction --no-owner --no-privileges --role=enot_app -U postgres -d <тестовая-база>`. Сверить каталог, ревизию Alembic и снимок исследования. Срок хранения и автоматические резервные копии согласовать с бюджетом, так как хранение и трафик тарифицируются. На этапе подготовки staging архива и проверенного восстановления Railway ещё нет.

Для отката приложения вернуть проверенный SHA API, воркера и frontend. Совместимость предыдущего API с текущей схемой проверить до отката. Для несовместимой миграции использовать проверенную копию на отдельной БД, сверить данные, затем переключить строку подключения и вернуть согласованные версии приложений.
