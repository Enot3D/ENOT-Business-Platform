# Аналитик TASK-007

Команда `python -m enot_api.cli worker` обрабатывает существующую очередь TASK-005. При стандартной конфигурации `AI_PROVIDER=local` воркер формирует локальную сводку и возвращает `fallback` с кодом `provider_disabled`. Если в выбранных нишах отсутствуют пригодные наблюдения, воркер возвращает `insufficient_data` и пробелы. Те же эндпоинты, статусы и поля доступны Frontend и снимкам отчётов.

Локальная сводка показывает факты из проверенных выдержек, расчётные диапазоны и сценарные показатели TASK-003, экспертные оценки преимуществ и недостатков, риски и гипотезы проверки спроса. В сводке оценки 4–5 обозначены как преимущества, оценки 1–2 как недостатки. Сравнение проверяет пересечение исходных диапазонов. Наблюдение из другой географии помечается в тексте. Пригодность выдержки проверяется по курируемому [реестру пилота](data/source-observations.tsv) и читаемой версии источника в том же выпуске. Новый выпуск должен иметь доступный воркеру проверенный реестр выдержек.

## Подключение провайдера

После утверждения владельцем провайдера, разрешённых данных и бюджета задайте в окружении **воркера** следующие переменные. Пример использует условные тарифы и адрес.

| Переменная | Пример | Назначение |
| --- | --- | --- |
| `AI_PROVIDER` | `chat-completions` | Адаптер HTTPS Chat Completions. Значение по умолчанию — `local`. |
| `AI_EXTERNAL_POLICY` | `pilot-reference-metadata-v1` | Включается после утверждения политики владельцем. |
| `AI_PROVIDER_URL` | `https://provider.example/v1/chat/completions` | Утверждённый HTTPS-адрес для JSON mode, `max_completion_tokens` и полей usage. |
| `AI_MODEL` | ID модели провайдера | Утверждённая модель с поддержкой этого формата. |
| `AI_API_KEY` | Секрет воркера | Передаётся только в заголовке авторизации настроенному endpoint. |
| `AI_TIMEOUT_SECONDS` | `15` | Общий таймаут запроса в секундах, максимум 20 при lease 30 секунд. |
| `AI_DAILY_BUDGET_MICRO_USD` | `1000000` | Общий суточный лимит в микро-USD. В примере 1 USD. |
| `AI_INPUT_MICRO_USD_PER_MTOK` | `1000000` | Тариф входа в микро-USD за миллион токенов. В примере 1 USD за миллион. |
| `AI_OUTPUT_MICRO_USD_PER_MTOK` | `2000000` | Тариф выхода в тех же единицах. В примере 2 USD за миллион. |

Перезапустите воркер с той же командой. Стандартная сеть `data` в Compose внутренняя. Для внешнего режима передайте перечисленные переменные через конфигурацию окружения воркера и разрешите ему egress до утверждённого провайдера в окружении развёртывания. Используйте одинаковые тарифы и лимит на всех воркерах одной БД. Для возврата к локальному режиму установите `AI_PROVIDER=local`. Ранее сохранённый успешный ответ может использоваться повторно в том же проекте при совпадении выпуска, результатов и версии промпта.

## Формат и ограничения

Промпт `task-007-evidence-v1` отправляет порядковые номера ниш, типы разделов и связей, признак совпадения географии, точность периода и пары UUID доказательства и наблюдения. Текст источников и полей проекта остаётся на сервере. Профиль, идентификаторы владельца и проекта, сырые документы и инструменты отсутствуют в теле запроса. HTTP-редиректы отключены. Модель возвращает JSON:

```json
{"references":[{"evidence_id":"<UUID>","observation_id":"<UUID>"}]}
```

Принимаются до 12 уникальных пар. Сервер проверяет обе ссылки и их связь с выбранным снимком. Он рендерит итоговые формулировки и числовые показатели из проверенных данных и шаблонов. Модель может менять приоритет выдержек внутри раздела. Она не пишет рекомендации и фактические утверждения. Сервер сохраняет обязательные разделы и показывает противоречащие свидетельства при наличии.

Ограничения очереди — одна активная работа и десять новых задач в сутки UTC на владельца. Для внешнего вызова проверяется консервативная оценка размера входа с пределом 8 000 токенов. Выход ограничен 1 000 токенов через параметр API. Фактический usage повторно проверяется перед применением ответа. Если провайдер добавляет сверхлимитные токены, ответ отклоняется и расход по его usage учитывается. Лимит расходов рассчитывается по заданному тарифу и usage провайдера. Это оценка, которую можно сверить с биллингом провайдера.

До сетевого вызова воркер фиксирует максимальный расчётный расход в БД. Конкурирующие воркеры учитывают этот резерв в общем лимите UTC. При таймауте или отсутствии достоверного usage резерв сохраняется до конца учётных суток. Автоматического повторного вызова нет. В `token_usage` сохраняются резерв или токены и расчётная стоимость, в снимке результата — версия рендерера, хеш контекста и выбранные ID доказательств. Эти служебные поля остаются внутри БД.

## Проверки

С изолированным PostgreSQL и установленным `backend/requirements-test.txt` из корня репозитория:

```bash
PYTHONPATH=backend python -m pytest -q backend/tests analysis/TASK-003/calculator
ruff check backend
openapi-spec-validator architecture/TASK-004/api-contract.yaml
```

Оценочный набор использует ниши 03, 04 и 15, локальный `stub/fixture-v1` и подменённый HTTP-транспорт. Проверены корректный ответ, неизвестные и несовпадающие ссылки, дубли, выдуманное число, нехватка данных, неверный JSON, таймаут, подмена источника, повтор запроса, лимиты токенов и квот, одновременная попытка расходования бюджета. Реальные вызовы LLM не выполнялись. Токены и расход в тестах заданы фикстурами.
