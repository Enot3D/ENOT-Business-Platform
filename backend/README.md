# Backend MVP ENOT Business Platform

FastAPI и воркер используют одну PostgreSQL. Маршруты продукта описаны в [OpenAPI TASK-004](../architecture/TASK-004/api-contract.yaml). API возвращает утверждённую схему по `/openapi.json`, а тесты сверяют её с зарегистрированными операциями и фактическими HTTP-ответами.

## Запуск и интерфейс для TASK-009

Нужны Python 3.12 и PostgreSQL 15 или новее. При сборке из корня репозитория сохраните рядом с `backend/` каталоги `analysis/TASK-003/`, `research/TASK-002/` и `architecture/TASK-004/`. Импорт, калькулятор и OpenAPI используют эти файлы.

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | DSN PostgreSQL. Поддерживаются `postgresql://` и `postgresql+psycopg://`. API и воркер используют одну базу. |
| `APP_ORIGIN` | Внешний origin фронтенда и API, например `https://enot.example`. Указывается без пути и завершающего слеша. |
| `APP_SIGNING_KEY` | Общий секрет экземпляров API длиной не менее 32 байт для CSRF и курсоров. |
| `APP_COOKIE_SECURE` | По умолчанию `true`. Значение `false` допустимо для локального loopback. |
| `TEST_DATABASE_URL` | DSN отдельной тестовой PostgreSQL. Тестовая роль должна уметь создавать схемы. |

Команды выполняются из `backend/` в активном виртуальном окружении.

```sh
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m enot_api.cli import
python -m enot_api.cli create-user owner
python -m uvicorn enot_api.main:app --host 0.0.0.0 --port 8000
```

Для локального HTTP задайте `APP_ORIGIN=http://localhost:8000` и `APP_COOKIE_SECURE=false`. Секрет можно сгенерировать командой `python -c 'import secrets; print(secrets.token_urlsafe(48))'`. Пароль учётной записи CLI читает через интерактивный ввод. Держите UI и API на одном origin. Браузер передаёт cookie `enot_session`, заголовок `Origin` на POST/DELETE и выданный сервером `X-CSRF-Token` на аутентифицированные записи. Клиент повторяет `Idempotency-Key` при повторе записи.

- Миграция и импорт выполняются до открытия API для UI. `GET /healthz` проверяет процесс, `GET /readyz` проверяет доступность PostgreSQL и таблицы выпуска. После импорта доступен `GET /api/v1/datasets/current` с сессией.
- Воркер запускается отдельно командой `python -m enot_api.cli worker`. Для одной задачи используйте `worker --once`. Ключ ИИ не требуется. После получения lease воркер строит локальную сводку либо возвращает `insufficient_data`. Просроченный lease завершается статусом `failed`.
- Контракт расширения для TASK-007 находится в [worker.py](enot_api/worker.py). Адаптер принимает только утверждённые наблюдения и пробелы, а возвращает ID наблюдений. Текст формирует сервер. Перед подключением внешнего вызова в TASK-007 нужны таймаут вызова, учёт токенов и бюджета и проверка оценочной выборки.
- Каталог фильтрует бюджет по `start_min`. Клиент вычисляет статус из уже предусмотренных контрактом полей. Значение между `start_min` и `start_max` означает условное попадание, а бюджет от `start_max` покрывает диапазон. `null` означает отсутствие оценки.

## Выпуск и восстановление

Импорт выполняется одной транзакцией с блокировкой публикации. Он проверяет манифест, ссылки и полноту входов, хранит SHA-256 файлов, версию калькулятора и точные дроби. Повтор команды возвращает ID того же выпуска. Для нового подготовленного выпуска передайте `--version <version>`. Старые отчёты открывают сохранённые снимки с контрольной суммой.

[Связи ниш с аудитом](data/niche-evidence.csv) и [выдержки из аудита](data/source-observations.tsv) курируются в репозитории. Поля, которых нет в утверждённых входах, остаются пустыми либо маркируются гипотезами. В каталоге покрытие задано на уровне РФ. География пилота, рекомендованная в исследовании, сама по себе покрытия региона не устанавливает.

Начальная миграция создаёт схему. Путь восстановления после сбоя импорта — исправить входы и повторить команду: транзакция откатится целиком. Для базы с пользовательскими данными применяйте восстановление из резервной копии. `alembic downgrade base` удаляет таблицы и предназначен для проверки на пустой тестовой схеме.

## Проверки

```sh
python -m pip install -r requirements-test.txt
python -m pytest -q tests ../analysis/TASK-003/calculator/test_model.py
python -m ruff check enot_api migrations tests
python -m ruff format --check enot_api migrations tests
```

Тесты создают отдельную случайно именованную схему и удаляют её после прогона. Проверяются миграции, повтор и откат импорта, контракт, расчёты и источники, конкурентный повтор записи, снимки после публикации следующего выпуска, изоляция двух аккаунтов и очередь без ключа ИИ.
