# План реализации

Владелец назначает исполнителей вручную после приёмки спецификации. Текущий статус указан в карточке каждого задания.

| Задание | Вход и зависимости | Критерий готовности |
| --- | --- | --- |
| [TASK-005 Backend](../../tasks/active/TASK-005.md) | TASK-004, калькулятор и аудит | Миграции, импорт, расчёт, сессии, доступ, API и сохранение работают с тестовой БД. Есть контракты для интеграции ИИ. |
| [TASK-006 Frontend](../../tasks/backlog/TASK-006.md) | TASK-004 для разработки на фикстурах, TASK-005 для интеграции | На телефоне и компьютере пройден сценарий от фильтра до повторного открытия; источники и пропуски видимы. |
| [TASK-007 AI Engineer](../../tasks/backlog/TASK-007.md) | TASK-004 для заглушек и набора оценок, TASK-005 для очереди и API | Проверены привязки к источникам, сбои, подмена ID, квоты и корректная обработка отсутствия данных. |
| [TASK-008 QA](../../tasks/backlog/TASK-008.md) | TASK-005–007 и среда TASK-009 для итоговой проверки | Есть матрица R1–R7, воспроизводимые доказательства и статусы дефектов. |
| [TASK-009 DevOps](../../tasks/active/TASK-009.md) | TASK-004 для каркаса, выходы TASK-005–007 для полного Compose | Чистый запуск, миграция, импорт и проверки воспроизводятся в Compose и CI. |

Критический путь проходит через приёмку TASK-004 → TASK-005 → интеграцию TASK-006 и TASK-007 → совместный прогон TASK-008. Контур TASK-009 запускается параллельно и сходится перед итоговым прогоном. Если окружение задержится, оно становится блокером приёмки. Frontend готовит экраны и фикстуры на принятом OpenAPI; AI Engineer — адаптер и тестовую выборку на утверждённой схеме; QA проектирует проверки по контракту с начала работ. Изменения контракта сопровождаются обновлением фикстур и критериев в том же PR.
