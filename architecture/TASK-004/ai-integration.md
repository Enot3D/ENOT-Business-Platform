# ИИ-интерпретация

API принимает project_id, dataset_id, model_version и 1–5 niche_ids. Сервер проверяет доступ и разрешает IDs в неизменяемые результаты. Набор контекста включает факты, расчёты, допустимые оценки, пробелы и идентификаторы наблюдений. Профиль пользователя, секреты, свободный промпт и сырые документы исключены из контекста. Из источников идут только проверенные разрешённые поля, экранированные как данные. Вызов модели не имеет сетевых инструментов или права изменять состояние.

Адаптер принимает пакет наблюдений и типизированный запрос объяснения, возвращает candidate JSON, usage и идентификаторы провайдера/модели. Ответ — список элементов kind, statement, observation_ids. Выходной текст строится из одобренных утверждений и структурированных шаблонов. Числа подставляет сервер из типизированных полей наблюдений и результатов. Неизвестные ID, новое фактическое утверждение, неподдерживаемый факт источника и свободные числовые значения отклоняются. Эксперименты маркируются гипотезами. При отсутствии пригодного контекста сервер возвращает insufficient_data с перечислением пробелов; при отказе провайдера или валидации используется детерминированная сводка, отмеченная как fallback. Риск смыслового искажения проверяется оценочной выборкой с ручной сверкой. К результату сохраняются версия промпта, модель, хеш контекста, IDs результатов, валидация и затраты.

## Очередь и расходы

API резервирует квоту и создаёт запись queued в одной транзакции. Воркер выбирает запись FOR UPDATE SKIP LOCKED и присваивает lease; успешный результат, статус и расчёт фактических затрат записываются атомарно с проверкой владельца lease. Предложенные лимиты — 1 активная работа на владельца, 10 запросов/сутки, 8 тыс. входных и 1 тыс. выходных токенов на вызов, таймаут 30 с и максимум одна повторная попытка при подтверждённом отсутствии обработки. При неопределённом результате вызова после таймаута сохраняется резерв и выдаётся fallback/ошибка; автоматический повтор исключён. Внешний провайдер включается после решения владельца о лимите расходов и допустимых данных. Локальная заглушка покрывает happy path, сбой, неверный JSON, чужие ID, отсутствие данных и вредоносный текст.

Idempotency-Key повторно возвращает тот же ресурс при том же содержимом, иной payload даёт 409. Повтор после терминального сбоя делается с новым ключом в пределах квоты. Совпадение версии, контекста, владельца и проекта позволяет повторно использовать проверенный готовый вывод. 202 возвращает ID и status_url; GET выдаёт актуальное состояние. В отчёт включается только терминальный результат подходящего проекта, выпуска и набора ниш.
