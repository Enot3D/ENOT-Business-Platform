# Безопасность и качество данных

- Начиная с TASK-011 обычный пользователь регистрируется через `/register`. API проверяет Origin, формат email и пароль, ограничивает регистрацию по IP соединения, email и общему числу запросов. Создание аккаунта и сессии выполняется одной транзакцией. Уникальность email проверяется в PostgreSQL. Пароли хешируются Argon2id. Существующие аккаунты могут войти по прежнему логину.
- Сессия использует случайный токен в host-only cookie с HttpOnly, Secure и SameSite=Lax. В БД сохраняется хеш токена. Вход ограничен по аккаунту и IP, выход отзывает сессию. Запись в авторизованной области проверяет Origin и X-CSRF-Token. Смена пароля отзывает предыдущие сессии и создаёт новую.
- Запросы к проектам, отчётам и ИИ фильтруются по владельцу. Для чужого ID используется 404. Чтение каталога одинаково для аутентифицированных пользователей. Тестовая вторая учётка проверяет изоляцию.
- Pydantic проверяет параметры, UUID, enum, размер списка, бюджет, лимиты тела и пагинацию. SQL параметризуется. Сервер отдаёт стабильный код ошибки и request_id. HTML из источников выводится как текст. Ссылки допускают http/https; API не скачивает URL из клиентских запросов.
- В Git и образах только имена переменных. Ключ провайдера получает воркер. Логи содержат идентификаторы и технические статусы без паролей, секретов, текстов источников и частных отчётов. Внешние вызовы следуют ограничениям [ИИ](ai-integration.md).
- Импорт из утверждённых материалов. У недоступного источника фиксируются причина, дата доступа, разрешённый фрагмент или указание на его отсутствие. Индекс и альтернативный URL маркируются по своему происхождению. Запись факта требует проверки определения, географии, периода и допустимости использования. Хеши входов, версии и метки обеспечивают повторный расчёт.
- Восстановление проверяется на локальной копии PostgreSQL. CI использует тестовые данные и заглушку модели. Изменения production запрещены правилами проекта. Платные ресурсы требуют отдельного разрешения владельца.
