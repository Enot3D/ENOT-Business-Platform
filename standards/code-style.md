# Оформление кода и документации

- Следуй конфигурации форматтера, линтера и сборки существующего модуля. Если её ещё нет, зафиксируй используемые команды и согласованный стиль рядом с кодом.
- Используй понятные имена. Для публичных API описывай поля, единицы, допустимые значения и ошибки. Сохраняй совместимость или согласуй изменение контракта.
- В SQL используй параметризованные запросы. Оформляй изменения схемы версионированными миграциями. Фиксируй зависимости способом, принятым в модуле.
- Держи изменения в границах задачи. В Markdown используй UTF-8 и относительные ссылки на файлы репозитория. Обновляй примеры вместе с контрактом.
- Применяй [стандарт тестирования](testing.md) и [стандарт безопасности](security.md) перед коммитом.
